# Superseded designs

These designs were replaced by later accepted decisions. They are retained to
explain why older handoffs or implementation notes may use different terms.

| Superseded design | Current replacement | Current owner |
|---|---|---|
| Keep one permanent reusable ResyncEngine and reset its processors and children through acknowledged Begin and Deactivate barriers. | Construct one non-reusable ProcessingSession actor tree per attempt and terminate it through a consuming shutdown barrier. | [Processing lifecycle](../architecture/processing-lifecycle.md) |
| Complete the initial scan before subscribing, then repair only from final VSPC. | Catchup overlap and ordinary recovery. | [Processing lifecycle](../architecture/processing-lifecycle.md) |
| Create placeholder block rows at levels 0/1 and promote them later. | Boundary identities and separate materialized blocks. | [Domain model](../architecture/domain-model.md), [storage](../architecture/storage.md) |
| Treat any identity-row existence as block materiality. | `BlockPresence` states and the retained-past invariant included in `Materialized`. | [Domain model](../architecture/domain-model.md) |
| Prune VSPC history through `sink` using `<=`. | Strict-below-sink pruning. | [VSPC processing](../architecture/vspc-processing.md) |
| Estimate Catchup with a large sink-anticone window, tenfold merge-set margin, or fixed X/Y page rule. | Rolling-sink proximity and retained fallbacks. | [Processing lifecycle](../architecture/processing-lifecycle.md) |
| Allow only ResyncEngine reconciliation to request Rebuild. | Typed direct Rebuild requests. | [Processing lifecycle](../architecture/processing-lifecycle.md) |
| Gate global Live on a fixed body-tip snapshot, materiality batch, and bounded extra GetBlocks pages. | Overlap-based Live admission without a body-DAG completeness claim. | [Processing lifecycle](../architecture/processing-lifecycle.md) |
| Pass raw `SharedNodeBlock` values between components and derive a separate `BlockMaterialization`. | One flattened `ValidatedNodeBlock` crosses the NodeService boundary. | [Domain model](../architecture/domain-model.md), [NodeService](../architecture/node-service.md) |
| Preserve repeated direct-parent and merge-set positions in `ValidatedNodeBlock`, with parent canonicalization only inside Storage. | NodeService canonicalizes direct parents and each merge-set vector independently by first occurrence while constructing `ValidatedNodeBlock`. | [Domain model](../architecture/domain-model.md), [NodeService](../architecture/node-service.md#rpc-normalization), [storage](../architecture/storage.md) |
| Accept the block's own hash in a `ValidatedNodeBlock` relationship vector under the node trust boundary. | NodeService rejects own-hash references because Storage relies on their absence during materialization. | [Domain model](../architecture/domain-model.md), [NodeService](../architecture/node-service.md#rpc-normalization), [storage](../architecture/storage.md) |
| Use an `Auto` recovery mode that falls through from Resync to Rebuild. | Explicit Resync and Rebuild obligations. | [Processing lifecycle](../architecture/processing-lifecycle.md) |
| Defer the API outside KGI v2. | In-process API and Web-facing graph contract in v2. | [ApiService](../architecture/api-service.md), [API protocol](../architecture/api-protocol.md) |
| Identify API continuity with `GraphEpoch` stored on every graph image. | `GraphPublication.publication_id`, with views carrying only their own revision. | [API graph publication](../architecture/api-publication.md), [API graph model](../architecture/api-graph.md) |
| Carry `HeadGraphCoverage` in every delta. | Explicit graph mutations plus the delta lineage `head_level`. | [API graph model](../architecture/api-graph.md) |
| Recheck VSPC source/sink continuity inside ApiService. | Trust the ordered, continuity-certified `VspcProcessor` output. | [API graph model](../architecture/api-graph.md) |
| Use a cross-session observer stream, global invalid flag, and `InvalidateSession` control. | Fresh per-session graph-update ingress and `ApiService::reset`-owned supersession. | [API ingress](../architecture/api-ingress.md), [ApiService](../architecture/api-service.md) |
| Publish a database seed before locating its graph-update boundary and keep a private detector active. | Explicit construction and alignment before activation. | [API graph publication](../architecture/api-publication.md) |
| Let either overlapping publication runtime install, with the last completed installation winning. | ApiService fences publication installation and Rebuild gate reopening with a monotonic runtime generation. | [ApiService](../architecture/api-service.md) |
| Treat graph-update channel closure as an ApiService session event. | `ApiService::reset` is the sole ApiService session-supersession mechanism. | [API ingress](../architecture/api-ingress.md), [ApiService](../architecture/api-service.md) |
| Have ResyncEngine reset ApiService and deliver lifecycle markers directly. | Supervisor installs the session ingress; ProcessingSession owns lifecycle-marker delivery. | [Processing lifecycle](../architecture/processing-lifecycle.md) |
| Open graph-update ingress and start publication construction when processing reaches PostSeal, with BlockProcessor owning marker delivery. | Keep ingress closed through historical recovery and let the ProcessingSession-owned worker open it at Catchup. | [Processing lifecycle](../architecture/processing-lifecycle.md), [API ingress](../architecture/api-ingress.md), [API graph publication](../architecture/api-publication.md) |
| Require a successfully encoded tier-50 Head snapshot before publication installation. | Install an aligned publication immediately and construct every Head tier lazily through request-driven single flight. | [API graph publication](../architecture/api-publication.md), [API protocol](../architecture/api-protocol.md), [ApiService](../architecture/api-service.md) |
| Use completion of a Rebuild reset as the database-replacement barrier. | StorageService excludes API database phases with its replacement gate. | [Storage](../architecture/storage.md) |
| Have ApiService report API database-generation loss and Supervisor acquire and install context-specific replacements. | StorageService autonomously retires and replaces its API generation; Supervisor only forwards its ordered generation events to ApiService. | [Storage](../architecture/storage.md), [processing lifecycle](../architecture/processing-lifecycle.md), [ApiService](../architecture/api-service.md) |
| Have Supervisor obtain processing DB generations through `StorageService::wait_until_usable()`. | StorageService publishes ordered processing-generation events; Supervisor retains the current generation only for construction of a new processing session. | [Storage](../architecture/storage.md), [processing lifecycle](../architecture/processing-lifecycle.md) |
| Have Supervisor obtain RPC generations through `NodeService::wait_until_usable()`. | NodeService publishes ordered RPC-generation events; Supervisor retains the current generation only for construction of a new processing session. | [NodeService](../architecture/node-service.md), [processing lifecycle](../architecture/processing-lifecycle.md) |
| Pass the current node pruning point into a storage reconciliation snapshot and require it to be materialized locally. | Storage returns only fresh local stored session state; ProcessingSession tests the committed database sink against the node, while the current node pruning point is used only to prepare Rebuild. | [Storage](../architecture/storage.md#stored-session-state--settled), [processing lifecycle](../architecture/processing-lifecycle.md#resync-preparation) |
| Generate dedicated server-side Head-bounded Fixed delta projections. | Fixed windows reuse canonical cached Head deltas and request only missing retained level values. | [API protocol](../architecture/api-protocol.md), [Web](../architecture/web.md) |
| Construct each Head snapshot at its exact requested depth and current revision, with only optional exact-response reuse. | Publication-scoped configured cache tiers provide shared snapshots and canonical deltas connect their exact cursors to current Head. | [API protocol](../architecture/api-protocol.md), [API graph publication](../architecture/api-publication.md) |
| Reuse an eligible completed or running larger Head tier, and serve a soft-aged selected tier while starting its refresh. | Each request uses only its exact selected tier; an eligible hit starts no work, and a query physically removes its selected entry after 90 seconds of publication-local graph time. | [API protocol](../architecture/api-protocol.md#publication-scoped-head-response-cache--settled), [ApiService](../architecture/api-service.md#cache-and-encoding-jobs) |
| Complete or join selected-tier construction before evaluating `If-None-Match` whenever no eligible completed Head tier exists. | A construction-required conditional request first evaluates a floor-admitted current-tier semantic identity and can return `304` without creating or completing encoded cache work. | [API protocol](../architecture/api-protocol.md#publication-scoped-head-response-cache--settled), [API graph publication](../architecture/api-publication.md#publication-synchronization-and-request-capture--settled), [ApiService](../architecture/api-service.md#cache-and-encoding-jobs) |
| Let Synchronizing delta clients descend below the adaptive interval and chase every available intermediate Head. | Synchronizing and Live use the same adaptive near-Head target and wake schedule; only terminal Stale descends below the interval to its fixed final Head. | [API protocol](../architecture/api-protocol.md#canonical-head-delta-responses--settled) |
| Use fixed 15/30-revision convergence spans, destination heat and bridge selection, immutable source-keyed responses, and target-level cache pruning. | Use atomic-history dyadic catch-up, replaceable source entries, an adaptive bounded advancing-publication interval, and query-driven five-minute cache-age pruning without destination heat. | [API protocol](../architecture/api-protocol.md#canonical-head-delta-responses--settled), [ApiService](../architecture/api-service.md#cache-and-encoding-jobs) |
| Run distinct target-keyed constructions concurrently for one source revision. | Serialize construction behind one source-keyed fixed-target job, with size selection completed before job election. | [API protocol](../architecture/api-protocol.md#canonical-head-delta-responses--settled), [ApiService](../architecture/api-service.md#cache-and-encoding-jobs) |
| Encode an atomic delta through the hard-limit check before discovering an uncrossable replay boundary, then retain that boundary as a cache-owned serving floor. | Treat an atomic estimate reaching the soft limit as an append-time history replay boundary, and require every below-soft canonical delta body to fit the hard limit. | [API graph model](../architecture/api-graph.md#revision-and-history-advancement--settled), [API protocol](../architecture/api-protocol.md#graph-http-compression--settled) |
| Compose every selected Head-history interval into one public delta patch. | One cached response preserves its selected history entries as ordered replay units under a shared dictionary, and the Web replays them against publication-local timing. | [API protocol](../architecture/api-protocol.md), [Web](../architecture/web.md) |
| Publish a new Head view revision before appending its delta to independently locked history. | Atomically expose lifecycle state, Head view, and retained history through one publication core; no completion task or pending mutation survives caller cancellation or publication abandonment. | [API graph publication](../architecture/api-publication.md#publication-synchronization-and-request-capture--settled), [API graph model](../architecture/api-graph.md#revision-and-history-advancement--settled) |
| Retain full `u64` domains for graph levels, coordinate slots, and level sizes in canonical and public values. | Use `u32` graph levels and depths plus bounded `u16` coordinate slots and level sizes; retain `u64` for revisions, timestamps, scores, publication IDs, and byte counters. | [Domain model](../architecture/domain-model.md#shared-value-types--settled), [API graph model](../architecture/api-graph.md#graph-values-views-revisions-and-history--settled), [API protocol](../architecture/api-protocol.md#common-transport-dto-rules--settled), [Storage](../architecture/storage.md#persistent-representation--settled) |
